## 2. 逐段脚本

### 0:00–0:30 开场

**操作**：页面停在初始工作台，鼠标指向左栏文档库。

**说什么**：

> 这是 OfficePilot，一个本地优先的办公文档工作台。它解决的不是「聊天」，而是把公司里的制度、会议纪要、表格变成**可引用、可校验、可导出**的结果。演示公司是虚构的星海科技，知识库里已经有 7 份文档：差旅、信息安全、考勤、会议、供应商评分、培训预算和采购合同。

**预期画面**：左栏 7 份文档，分类筛选显示「全部 7 / 制度 4 / 会议 1 / 表格 1 / 合同 1」。

---

### 0:30–1:10 文档库与入库

**操作**：

1. 鼠标依次点左栏分类「制度 / 会议 / 表格 / 合同」，再点「全部」。
2. 指向某份文档的元信息（如「制度 · 1 块 · 48 KB · 已入库」）。
3. （可选，时间允许）在「分类」选「制度」，点「上传文档」，选择一份准备好的 Markdown；观察「排队中 → 解析中 → 切块中 → 向量化 → 已入库」。

**说什么**：

> 支持 PDF、DOCX、XLSX、Markdown、TXT、CSV 六种格式。上传后是异步串行入库：解析、切块、向量化、写 FTS 和向量索引，状态和块数在左栏可见。上传按 SHA-256 去重；重启后数据仍在 SQLite 里。时间关系这里不现场传大文件，讲状态机即可。

**预期**：分类计数正确；已入库文档显示块数；上传时进度变化。若上传重复文件，会提示「该文档已存在」——可以顺势讲去重。

### 1:10–2:10 制度问答 + 引用定位

**操作**：

1. 确认在「制度问答」技能。
2. 点击快捷问题 **「一线城市住宿标准是多少？」**。
3. 等待流式回答结束；指向结论块中的 **650 元 / 120 元 / 3 个工作日**。
4. 点击正文中的引用上标 **`[1]`**。
5. 右侧自动切到「证据」页签，指向高亮的原文片段、文件名、页码、相似度。

**说什么**：

> 这是 RAG 的主链路：查询向量化 → 向量 + FTS5 中文 bigram 混合检索 → 阈值过滤 → 只把命中的片段给模型 → 流式生成，并要求每段结论后带 `[n]` 引用。点击 `[1]`，右侧定位到原文，能看到文档名、页码、片段编号和相似度。引用不是装饰，是校验过的。

**预期**：

- 回答含 `650`，并带 `[1]`。
- 右侧「证据」出现 2 条左右来源，第一条为《员工差旅费用管理办法 v3.2.pdf》。
- 点击引用后对应证据项高亮。

**如被问「为什么还有别的文档」**：检索是全库混合排序，相似度高的前几条都会展示；回答只引用与结论相关的片段，校验会检查引用编号和数字是否能在引用片段中找到。

### 2:10–2:40 回答边界

**操作**：点击快捷问题 **「海外出差怎么报销？」**。

**说什么**：

> 这是回答边界。演示知识库故意没有境外差旅规定。系统检索不到高于阈值的依据，就不会调用模型硬答，而是返回「边界」结论、缺失资料清单和转人工建议。后面的引用校验如果失败，也会降级成「无法确认」，而不是编造。

**预期**：

- 结论块标签为「边界」，琥珀色警告样式。
- 出现「建议转人工 / 补充资料」卡片，含缺失资料与转人工说明。
- 可以点「复制转人工说明」。

**注意**：demo 模式下这句话可能先检索到弱相关片段，然后因引用校验失败降级为边界；这是设计中的降级路径，不是系统崩溃。

### 2:40–3:50 结构化抽取

**操作**：

1. 点技能 **「文档抽取」**。
2. 在输入框输入 **`@Q3`**。
3. 在弹出的文档选择器中用鼠标点 **「Q3 产品评审会纪要.md」**；输入框上方出现 **「已引用」** 标签。
4. 字段面板保持 **「会议行动项」**（任务 / 责任人 / 截止日期 / 优先级 / 风险）。
5. 点击快捷指令 **「抽取这份会议纪要的行动项」**。
6. 等待右侧自动切到「结果」页签；指向表格的 **「任务」** 列和 **5 行**数据。
7. 点击 **「导出 CSV」**。

**说什么**：

> 抽取先用 `@` 指定一份文档，再选字段模板。模型只输出 JSON 数组，后端用 zod 逐行校验 schema；失败会把错误回灌重试一次。正常路径这里一次通过，所以现场看到的是 5 行干净数据，不会为了演示伪造一次失败。CSV 带 UTF-8 BOM，Excel 打开中文不乱码。

**预期**：

- 对话区显示「已抽取 5 行结构化数据，字段校验通过」。
- 右侧表格列为「任务 / 责任人 / 截止日期 / 优先级 / 风险」，5 行。
- 「导出 CSV」下载 `会议行动项.csv`。

**如被问「失败重试怎么证明」**：说明 `extractStructured` 最多 2 次尝试，失败发 `validation` 事件；单测 `extract.test.ts` / `extract.graph.test.ts` 覆盖非法 JSON → 重试 → 成功或告警。

### 4:35–5:15 执行链路

**操作**：

1. 点右侧 **「执行链路」** 页签。
2. 指向 Router / Retrieve / Generate / Validate 的节点耗时和 detail。
3. 如果有引用校验记录，指向「第 N 次 · 未通过 / 通过」。

## 4. Q&A 话术

### 4.1 架构

**问：为什么选这套技术栈？**

> 全 TypeScript 单仓，前后端共享 zod 契约；Fastify 的流式、上传、静态托管插件成熟；`node:sqlite` 是 Node 24 内置，避免原生编译依赖；LangGraph 用显式状态图表达路由，答辩时能讲清条件边和重试，而不是把所有逻辑塞进一个 prompt。

**问：为什么不用向量数据库？**

> 单机演示、文档量小，SQLite + FTS5 + Float32 BLOB 足够，备份就是一个文件。检索层做了接口隔离，换外部向量库不影响业务层。代价是并发写靠串行队列，不适合高并发多实例。

**问：三层怎么分？**

> 工作台只负责交互与展示；Fastify 负责入库、检索、运行编排与事件；网关与 SQLite 是最底层的模型和存储。前端不直接碰模型，所有引用、校验、边界都由服务端产出。

### 4.2 RAG

**问：检索具体怎么做？**

> 查询先 embedding；在 ready 文档范围内算向量余弦；同时用中文 bigram 分词查 FTS5 top-8；候选内把 BM25 做 min-max 归一化，按 0.75 向量 + 0.25 BM25 排序；按向量阈值过滤；相邻块去重；取前 5 条。阈值只作用于向量相似度。

**问：只靠向量不行吗？**

> 中文制度里有大量专有名词和数字，FTS 对精确词命中更稳；混合排序能改善顺序。但要诚实：FTS 只在向量候选内重排，不能救回向量完全漏掉的块，这是当前实现的限制，文档里写明了。

**问：怎么防止编造？**

> 三层：检索不到阈值不生成；生成必须带 `[n]`；生成后校验引用编号、日期、数字是否能在引用片段中找到，失败重试最多 2 次，仍失败降级为「无法确认」。文档内容只当数据，提示词明确不执行文档中的指令。

**问：评测为什么是 9/9，不是 10/10？**

> 前 9 条是事实题，统计 hit@3；第 10 条是故意构造的库外问题，期望拒答。所以指标是「9/9 命中 + 1/1 拒答」，不是把拒答题算作命中。demo provider 用 256 维 hash embedding，相似度整体偏低，所以评测阈值 0.1；真实 provider 默认 0.55。

**问：为什么第 10 题是引用校验降级，不是阈值直接拒答？**

> demo 回答对库外问题仍会先检索到弱相关片段，并生成一段不带引用的说明；引用校验发现没有引用，重试后降级为边界。这是设计中的第二条边界路径。检索层面确实没有高于阈值的强相关来源。

### 4.3 LangGraph / 状态图

**问：状态图体现在哪里？**

> 顶层是 LangGraph `StateGraph`：START → router，条件边分到 qa / summary / extract / weekly，四个分支各自结束。QA 内部是 retrieve → answer → validate → retry / degrade 的确定性循环，节点事件通过同一个 emitter 发 SSE。抽取内部是 JSON → zod → 失败重试。

**问：为什么 QA 的 validate 不单独做子图？**

> 当前实现把 QA 的校验循环收在节点内，UI 和事件协议上等价，但 LangGraph 图里看不到 validate 节点。这是有意的简化，架构文档里明确写了；如果继续做，会把 QA 拆成子图，暴露更细粒度节点。

**问：断线恢复怎么实现？**

> 运行和事件都落 SQLite；SSE 每条事件带递增 seq，`Last-Event-ID` 从 `seq > lastId` 补发；前端 EventSource 自动重连，连续失败时用 `GET /api/runs/:id` 对账，终态直接恢复结果。

### 4.4 边界与工程

**问：扫描件 PDF 支持吗？**

> 不支持。只用 unpdf 解析文本层；没有文本层返回 `DOC_PARSE_FAILED` 并提示先 OCR。这是明确的非目标，不假装支持。

**问：有鉴权吗？**

> 没有。默认只监听 127.0.0.1，定位本地演示；Docker 改 0.0.0.0 时需要自己加反向代理和访问控制。多租户、登录是明确的非目标。

**问：Docker 构建过吗？**

> 没有。本机没装 Docker，所以只交付 Dockerfile、.dockerignore 和 DEPLOY 命令，不声称构建成功。生产模式在本机用 `npm run build && npm start` 验证过。

**问：数据存在哪？重启会丢吗？**

> `data/officepilot.db` 和 `data/uploads/<docId>/`，SQLite WAL；重启后仍在。seed 是幂等的，按 SHA-256 跳过重复文档。

**问：并发怎么样？**

> 入库和运行都是进程内串行队列，避免 SQLite 写竞争和 embedding 限流；适合本地演示和小团队。高并发需要外部队列、多实例和真正的向量库。

### 4.5 AI Coding

**问：AI 在这个过程中做了什么？**

> XBuddy 负责拆任务、派发子代理、审查契约；子代理按 TDD 实现，每个阶段跑测试和类型检查。AI 生成的代码不是直接验收，下面这些缺陷都是测试或真实启动抓出来的。

**问：举一个 AI 写错、被你们抓到的例子？**

> 最典型的是生产构建：tsup 默认去掉 `node:` 前缀，把 `node:sqlite` 改成 `sqlite`，`npm start` 直接 `ERR_MODULE_NOT_FOUND`。测试和构建都是绿的，只有真实启动才暴露。修复是 `removeNodeProtocol: false`。另一个是静态托管路径用 `import.meta.url` 固定退四层，打包后多退一层，`/` 返回 404；改成从配置拿 `repoRoot`。

**问：还有吗？**

> 中文分词 `650元` 被当一个整体、FTS 删除后的孤儿行、重索引先写 hash 导致失败后无法重试、网关调用方 abort 被超时绕过、流式中途失败后切换 provider 导致答案重复、引用里的 `[1]` 被当数字、`650` 子串匹配 `6500`。每一条都有对应提交和测试。

**问：怎么保证 AI 没有糊弄？**

> 以可执行证据为准：162 个测试、typecheck、构建、E2E 6/6、评测 9/9 + 拒答、真实 `npm start` 和 curl。未验证的（Docker、真实模型、录屏）在报告里明确写「未覆盖」，不写成通过。

## 5. 演示时不要做的事

- 不要现场 `npm install`（依赖已装好）。
- 不要现场改 `.env` 或填 Key。
- 不要声称 Docker 已构建、真实模型已联调、录屏已完成。
